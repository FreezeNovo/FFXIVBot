# 10：P3 失败、退化与恢复的可定位诊断

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 05, 09
Spec: [P3 实施规格](../spec.md)
User stories: US05、US08、US23、US24、US28

## What to build

所有者可以解释“某篇公告为什么没发、某项活动为什么被排除、哪次发送结果未知”，从本机现有状态/文章/投递页面关联安全日志；应用重启后仍保留必要的诊断证据。

## 依赖与现状

依赖 [05](05-batching-and-recovery.md) 与 [09](09-preflight-and-freshness.md)，其前置覆盖NA、多区域和文章版本。前面的切片应已有基本失败记录，本任务统一贯通和验收，不允许它们先吞异常。当前捕获后返回的来源失败常不输出日志，投递拒绝原因较粗，未配置统一文件日志留存。

## 验收条件

- [x] P3各阶段失败包含可关联的源、文章/版本、内部目标、计划窗口/批次/attempt、错误类型和可获取的安全原因，不要求所有字段在每条日志中都存在。
- [x] 覆盖首次来源失败、部分详情失败、缺发布时间、机械比较/解析失败、超时、过旧排除、一次暂停、恢复、发送拒绝及unknown；正常变化和处理失败不能用同一种模糊文案表示。
- [x] 已被服务捕获并返回DTO的失败仍可定位；外层异常保留必要堆栈，分类后错误不因只打印“失败”丢掉可用HTTP状态或安全provider错误码。
- [x] 采用现有日志能力建立本地有界文件留存与控制台输出，文档说明位置、轮转/容量和查看方式；配置错误不得使业务默默失去全部诊断。
- [x] 来源状态页面能显示首次失败和部分失败，活动页面显示最后核实与本次处理，投递页面保持unknown不冒充成功；不为P3另建完整P5 Dashboard。
- [x] 使用内部UUID及来源文档身份关联；显式过滤连接URI、token、cookie、真实QQ/群标识及其他敏感字段，不记录完整请求凭据或任意原始provider响应。
- [x] 可重复失败有计数或节流，恢复可观察；日志轮转和重启不影响业务账本，账本不是靠解析日志恢复。
- [x] 诊断权限继续仅限所有者，普通群员不因故障获得内部连接细节。原先普通回复结果丢失等相邻缺陷只在阻断P3时修复，否则保留P5记录。
- [x] 固定伪凭据与敏感标记测试证明脱敏，临时日志目录测试输出和留存边界；本轮运行证据中没有真实账号或密钥。

## 验证与完成证据

注入受控失败后同时断言DTO、持久状态、本机可见原因与安全日志；不直接依赖完整堆栈字符串。更新WEBUI和运行说明，记录相关离线测试结果及日志保留策略。
