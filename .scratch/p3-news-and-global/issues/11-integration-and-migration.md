## 验收条件

- [x] 固定schema16旧库升级到最终schema，逐项比较来源快照、所有者、群开关/授权/显式范围、候选与attempt；旧region为单元素集合，公告新功能默认未订阅。
- [x] 覆盖各中间schema连续升级、重复迁移、失败后重试、首次版本化备份不覆盖、拒绝高版本降级；检查完整性与外键。
- [x] 在独立副本完成迁移预演、备份恢复后再次迁移；不删除表/库掩盖问题，不将迁移时间当作逐活动核实时间或公告发布时间。
- [x] 旧已发送日程键、unknown和归档目标保留，重启不回放旧队列；发布升级不能改变已有群授权或自动加入NA。
- [x] 真实应用装配的离线生命周期测试覆盖来源/详情/预查/三流工作任务启动与关闭、唯一本机监听和运行锁；全部网络被拦截，不加载真实配置或真实数据库。
- [x] 走通国服+NA、即时+汇总、离线补发、按时复查退化、一次暂停/恢复、消息分页与WebUI配置的组合场景。
- [x] 权限矩阵和既有国服维护/活动回归保持；fake provider接收后丢响应、发送中中断、两个群逐个失败不发生重复或假成功。
- [x] 按 [Linux环境规则](../../../UV-USAGE.md#linux-前置条件与环境恢复)执行 `bash scripts/check-linux.sh`，另验启动脚本语法、差异空白及文档链接；测试不依赖实时上游。
- [x] 当前运行、迁移、恢复、WebUI能力与TODO一致；目标/已实现/未真实验收明确分开，锁文件与依赖检查通过。
- [x] 形成离线验收报告：实际命令、结果、迁移证据、未覆盖项及12的受控验收前置条件。不得以旧94项历史记录代替新版本验证。
