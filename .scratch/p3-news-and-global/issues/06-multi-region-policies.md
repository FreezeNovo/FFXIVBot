# 06：三类消息独立多区域策略与摘要分组

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 04
Spec: [P3 实施规格](../spec.md)
User stories: US04、US13、US14、US15、US18、US23、US27

## What to build

所有者在同一群分别为公告、活动摘要和维护选择国服/NA，查询与摘要清楚分组；旧群升级后仍保持原策略，新增区域不会自动开启或补发历史。

## 依赖与现状

依赖 [04](04-immediate-announcements.md) 的公告策略。当前摘要/维护为一个 region 字段，领取时比较单值；多区域不能仅修改复选框。NA真实内容由07接入，本切片先用固定领域样本验证策略贯穿所有层，不宣称NA来源已完成。

## 验收条件

- [x] 三类消息流分别保存区域集合，WebUI 可独立读写；未支持区域不能作为已可用功能展示。空区域集合不得解释为自动订阅全部区域。
- [x] 旧单区域转换为单元素集合，保留开关、分类、显式日程/窗口、普通群员查询授权和历史；新增NA不改变现有群策略。
- [x] 同群国服与NA查询按区域分组，原文标题保持不变，显示标识来自结构化区域；默认未来活动窗口不被关闭。
- [x] 公告新增区域/分类只为新增范围建立生效点，原有范围基线和已发版本不重置；移除范围仅终止其未发送资格。
- [x] 维护观察和幂等身份包含必要来源/区域信息，两个provider文章ID恰好相同时不会相互覆盖；旧维护历史和日程键可继续识别。
- [x] 发送前复核消息覆盖范围；改变区域后不会发送旧页面中已排除区域的内容。已开始批次不重排成第二批，仍有效区域不因另一区域退化而被全局关闭。
- [x] 保持原已发送本地日期窗口的去重；迁移、修改发送时刻或切换区域都不造成同日已完成摘要重发。
- [x] 验证国服-only、NA-only、两区、三流不同集合、空集合、非法区域、逐区域失败及权限矩阵；普通群员不能经QQ改变区域策略。
- [x] 迁移可重复、可备份恢复，页面及说明明确当前来源支持状态，逐步迁移期间原国服功能可运行。

## 验证与完成证据

通过真实 WebUI DTO/路由、临时存储、共用 query/renderer 与 fake MessagingPort 验证整个范围选择。固定schema16库验证策略、候选、attempt字段保留。06可与05推进，但共享schema修改必须协调编号和兼容路径。
