# 02：可配置新闻发现周期并独立运行详情复查

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 01
Spec: [P3 实施规格](../spec.md)
User stories: US01、US02、US28

## What to build

所有者在本机 WebUI 调整新闻列表检查间隔后，应用按持久设置运行发现任务，能看到最近结果；活动详情复查不随列表频率全量重复执行。

## 依赖与现状

依赖 [01 来源契约](01-source-contracts.md) 确认发现请求形态与退化边界。当前网关生命周期启动来源循环，列表刷新与最多40篇国服详情串行执行，随后固定等待六小时。仅调整常量不能完成本任务。

## 验收条件

- [x] 按 [官方资讯订阅](../../../GOAL.md#1-官方资讯订阅)提供默认周期和正整分钟配置，保存后可读回并跨重启保留；拒绝零、负数及小数，不将设置放进连接凭据文件。
- [x] UI、应用设置和后台实际唤醒使用同一配置；修改周期无需重启且不会创建第二个同源循环，明确显示最近尝试、结果及下次计划。
- [x] 将列表发现与详情复查分别编排；缩短列表周期不会重新拉取全部历史正文，活跃长周期活动的复查仍存在。
- [x] 生命周期继续由唯一应用承载；业务编排位于应用/runtime，NoneBot 只注册钩子。停止时正确取消工作，不遗留线程结果修改已结束的发送批次。
- [x] 同源重叠唤醒合并或串行化，不在上次未结束时无限堆积刷新；重启恢复按持久策略计算下一步，不补跑停机期间每个轮询刻度。
- [x] 单源超时、限流、无效响应和部分分页失败可见，其他源继续；失败不清空旧快照，也不阻塞摘要调度。
- [x] 测试从 WebUI 保存间隔到受控时钟推进、fake HTTP 调用及持久状态展示，验证默认15分钟、修改间隔、重启、并发唤醒与关闭。
- [x] 更新当前运行说明及 TODO，说明配置入口和周期含义，不声称发布后必在一个周期内送达。

## 验证与完成证据

优先复用 SourceTests、WebAccessTests、RuntimeLifecycleTests 的入口；新增可控时钟，禁止用真实睡眠等待周期。保存相关测试结果及离线生命周期验证。涉及设置迁移时附旧库重跑与备份测试。
