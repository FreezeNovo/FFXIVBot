# 04：国服即时新公告与内容变动通知

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 03
Spec: [P3 实施规格](../spec.md)
User stories: US03、US04、US05、US06、US09、US10、US13、US26

## What to build

所有者在 WebUI 为一个群启用国服公告后，只有符合订阅条件的新文章和后续内容变动进入独立公告流，复用现有投递账本发送，并在页面预览和历史中可见。

## 依赖与现状

依赖 [03 文章版本](03-document-versions.md)。不依赖02的周期改造：人工或既有周期刷新也能验证本切片。当前 claim_notification 只认可活动摘要和维护流，需要为公告增加明确资格复核，而不是复用维护开关。

## 验收条件

- [x] 新增群级公告策略、区域/稳定分类选择、开关及默认即时模式；新功能默认未订阅，白名单不等于自动订阅。预览与实际通知共用查询/renderer，预览不写成功 delivery。
- [x] 按 [产品规则](../../../GOAL.md#1-官方资讯订阅)保存启用水位线；首启、同秒边界、晚发现旧文、缺少官方发布时间分别有确定且可重启复现的结果，不用入库时间冒充发布时间。
- [x] 首次旧文建立对照基线；已有基线后机械内容变化形成更新。首次新文无需有活动时间即可通知；维护按独立流路由，不能在两流重复发送同一维护消息。
- [x] 关闭/重新开启及新增分类具有各自生效点，持续开启范围不重置；停用立即使未发送候选失去资格，历史不删除。
- [x] 持久保存群级观察、待通知状态、最后确认发送版本；观察后崩溃、保存候选前中断或完成发送后重启都不漏掉合法意图、不重复成功消息。
- [x] 为公告扩展原子领取校验：目标、策略、范围、版本、有效期；关闭策略期间已在途的结果可记录，随后不自动重发。
- [x] 只有有效 provider 消息 ID 才记成功；明确离线可重试，未知结果进入 uncertain。一个群失败不阻断另一群。
- [x] 尚未开始发送的同篇版本合并为最新；A→B→A 的净变化和已成功发送 B 后回到 A 分别测试，不能仅靠历史 hash 集合去重。
- [x] 固定临时库覆盖首次启用、权限矩阵、分类变化、重启、未知结果及原有活动/维护互不影响，迁移不清理旧账本。

## 验证与完成证据

主测试从 WebUI 配置和 fixture 来源刷新进入公告工作流，最后断言 fake MessagingPort 输出及 attempts。复用 ReliabilityRegressionTests、WebAccessTests、SourceTests 的模式。补充当前 WebUI 与迁移说明，完成状态需有实际测试结果。
