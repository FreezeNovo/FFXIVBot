# 08：逐活动核实记录、数据年龄与手动查询

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 07
Spec: [P3 实施规格](../spec.md)
User stories: US20、US22、US23、US25、US27、US28

## What to build

每项国服/NA活动都能回答“最后何时成功核实、最近复查失败在哪里”；手动查询和本机页面显示准确年龄、警告与最后有效内容，为自动摘要提供结构化新鲜度结果。

## 依赖与现状

依赖 [07](07-na-events-and-maintenance.md)，确保两区正文及有效时间证据都已接通。当前来源整体成功时间不能代表单篇成功；内容未变化会跳过存储，旧详情 fetched_at 不能直接充当可信逐活动核实时间。

## 验收条件

- [x] 持久保存对应有效内容版本的最后成功核实时间、最近尝试、失败分类与安全原因，能关联一文多活动；不能被另一篇或列表刷新成功覆盖。
- [x] 内容未变且既有解析有效的复查更新核实时间；有效详情304可复用其已验证内容，列表304不刷新全部活动年龄。
- [x] 新正文解析失败、已知活动解析为零、缺字段或时间歧义时，保留旧候选与旧核实时间，显示最近失败，不把HTTP200单独当作活动核实成功。
- [x] 部分文章成功不掩盖其他文章失败；源级健康与逐活动状态在查询DTO中分开，禁止用一个全局布尔值清空所有警告。
- [x] 新鲜度评估覆盖 [产品规则](../../../GOAL.md#2-活动状态摘要)的失败即提示、48小时与72小时边界，返回结构化有效/警告/过旧/未核实结果；不依赖主机时区。
- [x] 手动查询保留过旧记录并明确标记年龄、最后核实时间及失败原因；本机页面可定位到文章，预览不创建投递成功记录。
- [x] 迁移旧数据时不把迁移时间写成核实成功时间；无可信记录明确标记未核实，成功复查后恢复正常评估，旧快照与历史不删除。
- [x] 可配置阈值通过所有者本机管理，拒绝非正值和警告阈值不小于停发阈值等无效组合，保存/重启后实际评估一致。
- [x] 固定时钟覆盖48/72小时之前、恰好和之后，以及失败后恢复、parser改变、同文多活动、另篇成功、机器时区改变。

## 验证与完成证据

从fake HTTP复查进入临时存储，再调用共用查询与页面验证；保留小规模纯评估函数边界测试。旧schema固定库验证字段保留和未核实语义。此任务不宣称自动停发已实现，自动投递门禁由09完成。
