# 09：摘要前复查、按时发送与退化恢复

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 02, 06, 08
Spec: [P3 实施规格](../spec.md)
User stories: US18、US19、US20、US21、US22、US23、US24、US25、US26

## What to build

每日摘要提前复查即将展示的活动，到点按已完成结果和持久新鲜度生成消息。正常空结果静默，部分过旧仅排除相关活动，全量过旧一次提示暂停，恢复后继续正常摘要。

## 依赖

依赖 [02 独立来源编排](02-discovery-cadence.md)、[06 多区域策略](06-multi-region-policies.md)、[08 逐活动核实](08-event-verification.md)。不在网关handler或数据库领取事务中直接抓网页。

## 验收条件

- [x] 按群计划窗口准备待展示活动，复查覆盖正在进行、未来默认窗口与即将结束范围；同篇/同时间的多个群可复用有效复查结果，不重复耗尽上游配额。
- [x] 提前量是可调整的运行参数，持久配置并可查看；实施时结合有界请求预算给出文档化初值，不更改到点优先发送原则。
- [x] 到点重新查询：成功复查采用新结果，失败或尚未完成按本次未能核实处理；慢请求不能阻塞所有群或无限推迟发送。
- [x] 应用启动晚于预查时刻、重启、修改发送时间、后台刷新与预查重叠均可恢复；没有重复候选、并发重复发送或依赖仅存于内存的事实。
- [x] 自动摘要使用08的年龄判断：警告仍展示，过旧排除；手动查询使用同一query/renderer能力但明确展示带警告的旧记录，不伪造自动可发送资格。
- [x] 默认未来活动保持展示、结束窗口正确分组，多区域内容按区域分组；单活动/区域失败不阻断其他有效结果，并明确提示有内容因过旧未展示。
- [x] 来源正常且确实无符合条件活动时不发空摘要；源未同步/退化不能被表述为“没有活动”。
- [x] 全量过旧仅在同一持续故障首次摘要时刻创建暂停提示，持久故障周期和幂等键覆盖重启、重复唤醒、发送失败/unknown；WebUI持续显示原因。
- [x] 成功核实恢复后按当前状态恢复正常摘要，结束故障周期；下一次独立故障可重新提示，不回放故障期间每日空白摘要。
- [x] 延迟发送前复核当前策略、区域、数据年龄及本地当天截止。批次未开始可重新生成；已开始批次冻结，晚到复查结果不能制造当天第二份或重发已成功分页。
- [x] 48/72小时恰好边界、零条解析保留、部分分页成功、关闭策略、移除群及旧日程幂等键回归均通过。

## 验证与完成证据

主路径使用可控时钟、可阻塞/完成的fake HTTP、临时SQLite及RecordingMessaging，从本机配置走到可见消息与账本。复用CalendarWorkflowTests和ReliabilityRegressionTests；不得依赖真实睡眠或网络。保存暂停/恢复消息样例和运行参数说明。
