# 05：公告汇总、版本合并与离线补发

Status: ready-for-agent
Category: enhancement
Resolution: completed
Blocked by: 04
Spec: [P3 实施规格](../spec.md)
User stories: US10、US11、US12、US13、US26

## What to build

所有者切换公告发送模式后，群能收到按时间汇总的新内容；离线恢复时只收到有效窗口内遗漏内容的一次补发汇总。重复唤醒、模式切换与分页失败不会把已发送或结果未知的内容再次打包。

## 依赖

依赖 [04 即时公告闭环](04-immediate-announcements.md)。本任务复用其文章资格和群级基线，不另外建立一套绕过投递账本的批量发送。

## 验收条件

- [x] WebUI 可选择即时/汇总及汇总时间，默认值、北京时间语义和空结果行为符合 [产品规则](../../../GOAL.md#1-官方资讯订阅)；活动摘要日程不受影响。
- [x] 汇总按群、窗口、成员及分页持久规划；重复唤醒和重启不生成第二批；没有内容时不发空消息或伪造成功记录。
- [x] 同篇多次修改只保留可发送的最新版本，比较该群最后成功发送版本；原始历史仍可查看，已开始投递的页面和批次保持冻结。
- [x] 离线恢复补发使用已保存的资格时间证据，覆盖最近72小时窗口内/外及恰好边界；旧文章发布时间与后续变动观察时间分别保留，重启/重试不能刷新补发窗口。
- [x] 原即时候选与补发汇总成员互斥领取；已成功、sending 或 uncertain 的成员不能重打包为另一可发送消息。
- [x] 分页部分成功后失败、响应未知或进程中断，只处理仍具有明确未发送资格的部分；最后发送基线按确认结果推进，不能把整批提前记成功。
- [x] 即时与汇总切换、修改汇总时刻、关闭订阅、移除群时，尚未发送内容按当前策略收敛；不得产生两个模式同时消费同一通知的竞态。
- [x] 多群恢复彼此独立，某群持续失败不阻塞其他群；新公告不使用活动摘要当天截止规则冒充自身补发期限。
- [x] WebUI 预览和投递历史能解释批次、成员版本与跳过原因；迁移保留原即时公告 attempts。

## 验证与完成证据

使用可控时间、可中断 fake MessagingPort 和临时 SQLite 覆盖完整批次行为；重点断言消息内容、分页成员、尝试和成功基线。记录修改模式与重启恢复的回归测试结果，同步运行说明。
