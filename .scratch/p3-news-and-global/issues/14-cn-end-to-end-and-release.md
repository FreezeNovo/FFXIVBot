## 范围与失败语义

用户要求再验收一次国服新闻实时采集到推送的完整流程，验收后提交全部工作区更改并同步版本。沿用已明确的单一Bot/群；限定15分钟、最多1条主动消息、零命令回复。只操作新隔离验收库，精确目标与连接配置仅放被忽略的本地状态。正式库不升级，不部署或遗留日常调度。

使用实时官方列表与正文、生产采集/版本/策略/规划/投递服务及真实NoneBot端口；不能复制此前缓存或fixture代替实际采集。已发布文章使用明确标识的受控回放；先验证正常新订阅不补历史，再仅在隔离配置设置验收水位线。发送结果未知时保留账本并停止重发；失败不能伪造成功或超出单条预算。

## 验收条件

- [x] 有界实际采集国服列表与一篇正文，保留来源ID、官方发布时间、分类与版本。
- [x] 预览不创建投递；正常新订阅不补历史；选中文章经生产流程形成唯一待发候选。
- [x] 发送前持久attempt；真实群投递、provider精确读回与用户客户端确认均通过。
- [x] 重复tick与服务重建不重发；测试连接关闭、策略停用、锁释放，正式库校验和不变。
- [x] 0.3.0项目、锁文件、来源标识与当前文档同步，完整Linux检查通过。
- [x] 全部可提交更改含原工作区工作整理后提交；私有状态不入库；创建对应版本标签，记录远端状态。
